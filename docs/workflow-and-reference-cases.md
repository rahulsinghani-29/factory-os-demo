# Typed workflow and reference cases

The Workflow design chart overlays proposed message filters on the executable LangGraph. Dashed boxes are design proposals, not implemented runtime steps. The exact configured LangGraph remains separately downloadable in the app. Each step is labelled CODE, IF / ELSE, LLM CALL, or TOOL CALL. Photo OCR and text preservation have separate routes. Audio/video ends with an unsupported-input report. Failures route through a saved unclear result and then END.

PO details, handoff/QC status, the production plan and preceding messages are separate read-only tool adapters. They read the supplied synthetic snapshots. They do not call live factory APIs. The incoming event represents one WhatsApp-style upload/pasted message; the live connector is not configured. A supervisor hold does not create or send a real task.

The Eval criteria page has been restored to the original judge rubric and release policy. Ten authored reference cases remain in `data/golden_cases.json`; they are no longer shown on that page. Labels include source provenance, PO, line, as-of time, work state, incremental counts, reported total, expected risk, expected route/reason, QC status, evidence IDs, forbidden claims and reviewer status. The exact input and all source snapshots are kept with each case. Label answers never enter the inference prompt.

All ten cases are synthetic and pending independent review. They include valid progress/completion and necessary abstention, not only holds. They are text/prepared-transcript cases, not a photo/audio/video accuracy benchmark. G08 and G10 document known same-scope conflict and stopped-machine reasoning gaps. They are expected reference labels, not passing model results. The original rubric remains on the Eval criteria page. A reviewed media benchmark, automatic judge scoring and asynchronous sampling are not implemented.

Validation for this change: 89 offline tests in the full workspace; 23 standalone tests in the public subset. Tests cover graph reachability/END paths, unsupported media without model calls, failed/empty OCR, separate fixture-reader traces, label exclusion from prompts, read-only lookup identity checks and arithmetic consistency of authored examples. Streamlit AppTest checks the updated pages. One actual local Qwen 2.5 7B synthetic text run completed and returned clear/no sewing risk. That is a scoped text smoke test, not a new OCR benchmark or a full operational verification.

The chart is centered and uses right-angle connectors. Clear/unclear nodes are labelled "Prepare clear result" and "Prepare clarification request". They remain routing markers; Python templates prepare the report without another model call. The overview groups error exits; the exact configured graph exposes each one.

Proposed filters: classify relevance and explicit PO; otherwise read the previous three messages in the same conversation and inherit only a single unambiguous PO with clear conversational continuity. Ignore unrelated/ambiguous messages with no reply. There is no time-based suppression: every relevant message with an established PO continues. These filters and their extra LLM/tool calls are design proposals, not implemented. No runtime inference, review policy or evaluation rubric changed.
